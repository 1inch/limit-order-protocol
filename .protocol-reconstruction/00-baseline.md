### Solidity compiler settings

The detector reported `SOLC_SOURCE=manual-inspection-required` because Hardhat
holds compiler settings in executable configuration that cannot be read
statically. Read by hand from `hardhat.config.js` lines 22-32:

| Setting | Value |
|---|---|
| `version` | `0.8.30` |
| `optimizer.enabled` | `true` |
| `optimizer.runs` | `1_000_000` |
| `viaIR` | `true` |
| `evmVersion` | `networks[getNetwork()]?.hardfork \|\| 'cancun'` |

`evmVersion` is computed rather than fixed. With no network environment
variables set it falls back to `cancun`, recorded as **ASM-4**. Any later
observation that depends on EVM version must name the network it was taken
under, and none of these settings may change during this workflow: `viaIR` and
the optimizer run count affect generated bytecode, and a changed `evmVersion`
changes available opcodes.

### `yarn hardhat compile` — exit 0, 1.5s

Result: `Nothing to compile`. The `artifacts/` and `cache/` directories were
already present and current for the baseline commit (**ASM-3**).

Two classes of non-fatal warning were emitted and are part of the baseline
rather than defects introduced here:

1. Fourteen `Network 'X' not registered` lines (mainnet, bsc, sepolia,
   optimistic, matic, arbitrum, xdai, avax, base, baseSepolia, zksync-zkevm,
   zksyncTest, zksyncFork, zksyncLocal). These come from
   `@1inch/solidity-utils/hardhat-setup` `Networks.registerAll()`, which
   registers a network only when its RPC environment variables are present. None
   are set on this machine. This is the practical consequence of **OQ-2** and
   means no fork-dependent command can run in this environment as configured.
2. `Solidity 0.8.30 is not fully supported yet` from Hardhat 2.23.0, warning
   that features such as stack traces may misbehave. Upstream condition, not
   actionable here, and explicitly out of scope: upgrading Hardhat is forbidden
   by the stack-preservation policy.

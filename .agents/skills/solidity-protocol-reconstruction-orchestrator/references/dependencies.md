manifest wins and `scripts/validate-package.sh` fails.

## Forbidden

`NomicFoundation/hardhat-skills` also ships `migrate-hardhat2-to-hardhat3` and
`migrate-foundry-to-hardhat`, right beside the `hardhat` skill this orchestrator
loads. This workflow never migrates frameworks. Never activate them; if one is
installed, `check-dependencies.sh` reports it as `FORBIDDEN` so the agent knows
it is on disk. Migration is a separate task the user must start explicitly.

## Locally owned policies

These capabilities are provided by this skill rather than by a dependency:

| Capability | File |
|---|---|
| behaviour specification (Phase 5) | [bdd-policy.md](bdd-policy.md) |
| existing test-suite audit (Phase 6A) | [test-audit-policy.md](test-audit-policy.md) |
| framework preservation | the four `*-policy.md` files |

Phase 5 previously depended on an external `bdd-practices` skill from an
aggregator repository built by a crawler. It was dropped in 5.0.0: the content
was not in English, the source was not the authoritative publisher, and the
workflow needs Gherkin conventions tied to this skill's own ID registry.
Removing it from the manifest does not remove any installed copy from disk.

## Missing skill behavior

Do not approximate a missing specialist. Stop the affected phase, show the
command generated by `scripts/install-dependencies.sh`, and record the stop in
`STATUS.md`.
